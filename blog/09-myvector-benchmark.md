# 내가 만든 vector가 std::vector보다 빨랐다? 성능 측정에서 배운 것

## 궁금했던 것

`std::vector<int>`와 직접 만든 `MyVector<int>`에 `push_back`을 100만 번 하면 어느 쪽이 빠를까?

실행 전 내 예측:

> 똑같지 않을까? 일부러 std의 원리대로 만들었는데, 그래도 빠르다면 STL의 vector가 빠르겠지. 잘 설계된 거니.

## 실험 설계

`std::chrono::steady_clock`으로 두 반복문의 시간을 각각 쟀다.

```cpp
auto start = std::chrono::steady_clock::now();
for (int i = 0; i < 1000000; i++)
{
	m2.push_back(i);   // MyVector<int>
}
auto end = std::chrono::steady_clock::now();
// std::vector<int>도 똑같이
```

## 결과

### 첫 측정: Debug 빌드

> 흠, 내가 만든 vector가 30ms 빨라. 왜지?

```
Debug   : MyVector 4 ms  vs  std::vector 34 ms
```

Debug 빌드의 `std::vector`는 범위 검사, 반복자 검사 같은 디버그용 검사를 잔뜩 켜 두고, 작은 함수도 펼치지 않고 하나하나 호출한다. Debug 숫자는 속도가 아니라 검사의 양을 잰 셈이다. 성능은 Release로 재야 한다.

### 두 번째 측정: Release, 마이크로초

> 900 정도 더 빨라.

```
Release : MyVector 약 1,800 ~ 1,960 µs  vs  std::vector 약 2,560 ~ 2,970 µs
```

Release에서도 MyVector가 꾸준히 약 1.4배 빨랐다.

### 원인 찾기: capacity 찍어 보기

`push_back`을 20번 하면서 매번 `capacity()`를 출력했다.

```
MyVector    : 1 2 4 4 8 8 8 8 16 ... 16 32 32 32 32
std::vector : 1 2 3 4 6 6 9 9 9 13 13 13 13 19 ... 19 28
```

> 2의 배수가 아니라 1 2 3 6 9 13 19 28 이렇게 나와.

MSVC의 `std::vector`는 2배가 아니라 1.5배씩 늘린다. 100만 개까지 판을 이사하는 횟수가 2배는 약 20번, 1.5배는 약 35번이다. 이사할 때마다 새 판 할당, 전부 옮기기, 옛 판 해제를 하니까 이사가 많은 쪽이 느리다.

## 왜 그런가: 느린데 왜 1.5배를 쓸까?

2배로 늘리면, 판이 꽉 찬 순간 계란 하나만 더 넣어도 판이 두 배가 된다. 1,048,577개를 넣으면 capacity는 2,097,152가 되고, 거의 절반인 1,048,575칸(약 4MB)이 빈칸이다.

> 비어 있는 칸을 최소화하려고 했네.

- 2배: 이사가 적어서 빠르다. 대신 최악이면 거의 절반이 빈칸.
- 1.5배: 이사가 많아서 느리다. 대신 빈칸이 최대 약 1/3.

속도와 메모리를 맞바꾸는 설계 선택이고, 정답은 없다. 실제로 GCC의 `std::vector`는 2배, MSVC는 1.5배를 쓴다.

## 정리

1. 한쪽이 무조건 빠르다고 다 잘 만든 건 아니다. 상황에 따라, 조건에 따라 어디에 초점을 맞추고 만드는지가 중요한 거다.
2. 디버그 빌드와 릴리스 빌드는 차이가 있다.
3. STL의 벡터는 판을 1.5배 정도로 만들어 대입 속도가 느린데, 그 이유는 메모리 확보를 위한 전략이라는 것.
