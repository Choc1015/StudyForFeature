# 부모 소멸자에 virtual이 없으면 무슨 일이 생길까?

## 궁금했던 것

부모 자식 클래스 간의 소멸자를 가상 함수로 만드냐 만들지 않으냐의 차이를 알기 위해

## 실험 설계

Character와 Player는 부모 소멸자를 가상 소멸자로, no를 붙인 것은 그냥 소멸자로 만들었다.

두 쌍으로 나눈 이유: 부모 소멸자를 가상 함수로 했는지 안 했는지 대조하기 위해

부모 클래스를 변수 타입으로 하고 자식 클래스를 new로 생성해서 저장한 다음, delete로 해제하면 생기는 일을 관찰했다.

```cpp
int main()
{
	Character* c = new Player();
	noCharacter* nc = new noPlayer();

	delete c;
	delete nc;

	return 0;
}
```

## 결과

```
Player
Character
noCharacter
```

## 왜 그런가

virtual이 없으니 실제 객체가 Player인 걸 보지 않고 해당 변수 타입의 소멸자만 불린다.

자식 클래스의 소멸자가 호출되면서 잡아 둔 메모리를 해제해야 하는데, 해제가 안 되어서 메모리 누수가 생긴다.

자식은 부모의 데이터가 필요하기에 부모 -> 자식 순으로 생성자가 호출된다. 소멸자는 부모 -> 자식 순으로 소멸자가 호출되면 자식은 모르는 데이터가 생기니, 자식 -> 부모 순으로 소멸자가 호출돼야 정상적인 흐름으로 진행이 된다.

## 정리

1. 부모와 자식 간의 소멸자는 부모 소멸자에 virtual을 붙여야 한다.
2. 생성자와 소멸자의 순서는 부자의 관계를 잘 생각하자.
3. 메모리에 대해 깊게 이해하자.

## 더 궁금해진 것
